# React Bits

Open-source animated React component library by David Haz. MIT + Commons Clause license. Docs: https://reactbits.dev. Repo: https://github.com/DavidHDev/react-bits. You copy the source into your project (shadcn-style); it is not an npm package you import from.

## Workflow

1. **Find the component.** Search the catalog sections below. Never invent component names; if it is not in the catalog it does not exist in the free library.
2. **Pick the variant** from the project: language (JS or TS) and styling (CSS or Tailwind). Detect from `tsconfig.json`, `tailwind.config.*`, `@import "tailwindcss"`. Default to `TS-TW` if the project uses TS + Tailwind, else `JS-CSS`. Tailwind variants assume Tailwind is already set up.
3. **Install** with the CLI (below), or copy the source manually.
4. **Install dependencies** the component needs (listed in the catalog). The shadcn CLI installs them automatically; manual copy does not.
5. **Use it**: import from where the CLI placed it, and tune via props. Read the installed source file to see the real prop list and defaults; do not guess prop names.
6. **Verify**: check the browser console, mobile layout, and `prefers-reduced-motion`.

## Install commands

Install ID = `<ComponentName>-<LANG>-<STYLE>`, LANG is `JS` or `TS`, STYLE is `CSS` or `TW`.

```bash
# shadcn (needs a components.json; run `npx shadcn@latest init` first if missing)
npx shadcn@latest add https://reactbits.dev/r/SplitText-TS-TW
npx shadcn@latest add @react-bits/BlurText-TS-TW        # registry alias form, if @react-bits is configured

# jsrepo
npx jsrepo@latest add https://reactbits.dev/r/SplitText-JS-CSS
```

Notes:
- CSS variants ship a sibling `<Name>.css`; the component imports it relatively. Keep both files together.
- TS variants may need `@types/three` or `@types/matter-js`; the CLI adds them.
- Registry JSON lives at `https://reactbits.dev/r/<ID>.json` (readable via fetch if a CLI is not possible: each file has `content`).
- Very recent components may not yet be in the registry. Then copy from the repo: `src/content/<Category>/<Name>` (JS-CSS), `src/tailwind/...` (JS-TW), `src/ts-default/...` (TS-CSS), `src/ts-tailwind/...` (TS-TW).
- Source tree categories: `TextAnimations`, `Animations`, `Components`, `Micro`, `Backgrounds`.

## Key dependencies

- **gsap** (+ `@gsap/react`): most text and scroll components. GSAP plugins like SplitText and ScrollTrigger are imported from `gsap/...` and registered inside the component.
- **motion** (Framer Motion): enter/exit and stagger components. Import from `motion/react`.
- **three / @react-three/fiber / @react-three/drei**: 3D components.
- **ogl**: lightweight WebGL for shader backgrounds.
- Some use `matter-js`, `lenis`, `postprocessing`, or nothing at all. Always read the catalog "Dependencies" column.

## Integration rules

- **Next.js / RSC:** components are client components and start with `'use client'`. If you wrap them in a server file, import them from a client boundary. WebGL components touch `window`/`document`, so use `next/dynamic` with `ssr: false` if hydration errors appear.
- **Sizing:** backgrounds fill their parent. Put them in a `position: relative` container with explicit height, behind content (`position:absolute; inset:0; z-index:0`) and give content `position: relative; z-index: 1`.
- **Performance:** use at most one or two WebGL backgrounds per page, lazy-load them below the fold, and prefer lower `dpr`/particle counts on mobile. Do not stack heavy backgrounds with heavy cursor effects.
- **Accessibility:** respect `prefers-reduced-motion` (disable or simplify), keep real text in the DOM for text animations when possible, and keep contrast on animated backdrops.
- **Customization:** edit the copied source freely. That is the point of the library. Prefer props first, then CSS variables/classes, then source edits.
- **Do not hand-write from memory.** Prop names and defaults change between releases; open the installed file.

## Licensing and what not to do

- MIT + Commons Clause: you may use the components in apps, sites and products, including commercial ones. You may **not** sell, sublicense, or redistribute the components themselves (alone, in a bundle, or as a port/template pack). Same for the React Bits tools and sounds. Keep the copyright notice.
- When building a deliverable for a user, installing/copying components into their project is fine. Do not package the library as a standalone product.
- Free library = open source forever. **React Bits Pro** (pro.reactbits.dev) is a separate paid, license-gated registry (page blocks, app UI, templates). Pro items cannot be installed from the free registry and must never be guessed. Only mention Pro when the user needs full landing-page blocks, app UI/dashboards, or templates that the free library lacks.
- Official ports for other frameworks: Vue Bits (vue-bits.dev), Svelte Bits (sveltebits.xyz), Solid Bits (solid-bits.dev). Do not use React Bits directly in non-React projects; point to the port.

## Free tools on reactbits.dev (browser tools, not installable)

Background Studio (customize backgrounds, export video/image/code), Shape Magic (inner rounded corners, export SVG/React/clip-path), Texture Lab (noise, dithering, ASCII on images/video), Center Stage, Sound Lab. Exports are yours to use; do not resell them as packs.

## When sandboxed or offline

If the CLI cannot reach reactbits.dev (restricted network), clone the repo instead (`git clone --depth 1 https://github.com/DavidHDev/react-bits`) and copy the component folder for the chosen variant. For live truth, `https://reactbits.dev/llms.txt` is the maintainer's agent-oriented index (components, CLI formats, Pro catalog). The catalog below is a snapshot from repo commit `37f53df` (2026-11-24); for live data fetch https://reactbits.dev/llms.txt.

# Usage patterns

Prop names below were checked against repo commit 37f53df. Always re-read the installed file; props evolve.

## 1. Hero: shader background + animated headline

```tsx
// Paths depend on where the CLI placed the files (check `components.json` aliases).
import Aurora from '@/components/Aurora/Aurora';
import SplitText from '@/components/SplitText/SplitText';

export default function Hero() {
  return (
    <section style={{ position: 'relative', minHeight: '100svh', overflow: 'hidden', background: '#05060a' }}>
      <div style={{ position: 'absolute', inset: 0, zIndex: 0 }}>
        <Aurora colorStops={['#5227FF', '#7cff67', '#5227FF']} amplitude={1} speed={0.6} />
      </div>
      <div style={{ position: 'relative', zIndex: 1, display: 'grid', placeItems: 'center', minHeight: '100svh' }}>
        <SplitText text="Ship something memorable" tag="h1" splitType="chars" delay={40} textAlign="center" />
      </div>
    </section>
  );
}
```

Real props confirmed in source:
- `Aurora`: `colorStops, amplitude, blend, speed, height, scale, glow, brightness, layers, direction ('top'|'bottom'), mouseInteraction, intro, opacity, lightMode, paused, dpr, className, style`.
- `SplitText`: `text, className, delay, duration, ease, splitType ('chars'|'words'|'lines'|'words, chars'), from, to, threshold, rootMargin, tag, textAlign, staggerFrom, mask, effect ('fade'|'blur'|'flip'|'pop'|'skew'|'wave'), trigger ('view'|'load'|'hover'|'click'), loop, loopDelay, hoverEffect, color, accentColor, onLetterAnimationComplete`.

## 2. Next.js: avoid SSR/hydration problems with WebGL

```tsx
'use client';
import dynamic from 'next/dynamic';
const Aurora = dynamic(() => import('@/components/Aurora/Aurora'), { ssr: false });
```
`next/dynamic` with `ssr: false` must live in a Client Component.

## 3. Reduced motion

```tsx
import { useEffect, useState } from 'react';
export function usePrefersReducedMotion() {
  const [r, setR] = useState(false);
  useEffect(() => {
    const m = window.matchMedia('(prefers-reduced-motion: reduce)');
    setR(m.matches);
    const h = (e: MediaQueryListEvent) => setR(e.matches);
    m.addEventListener('change', h);
    return () => m.removeEventListener('change', h);
  }, []);
  return r;
}
// {reduced ? <div className="static-gradient" /> : <Aurora ... />}
```
Components with a `paused` prop can be frozen with it instead of unmounting.

## 4. Layering rules for backgrounds

- Parent: `position: relative; overflow: hidden; height/min-height set`.
- Background wrapper: `position: absolute; inset: 0; z-index: 0; pointer-events: none` (unless the background reacts to the pointer, in which case put listeners on the parent or leave pointer events on).
- Content: `position: relative; z-index: 1`.

## 5. Choosing components by intent

| Goal | Look in |
|---|---|
| Animated headline / typewriter / scramble / shiny text | `text-animations.md` |
| Custom cursor, click sparks, trails, scroll reveals | `animations.md` |
| Cards, galleries, docks, menus, carousels, counters | `components.md` |
| Toggles, buttons, loaders, hover details | `micro.md` |
| Aurora, particles, grids, waves, shaders, 3D scenes | `backgrounds.md` |
| Full landing-page sections, dashboards, templates | Not in free library: React Bits Pro (paid) or build from free pieces |

## 6. AI/MCP helpers

reactbits.dev documents using the shadcn MCP server to let agents browse and install components: `npx shadcn@latest mcp init --client claude` (also cursor, vscode, codex). Components are discoverable through the `@react-bits` registry once it is configured in `components.json`:

```json
{ "registries": { "@react-bits": "https://reactbits.dev/r/{name}.json" } }
```
(Verify against https://reactbits.dev/get-started/installation, as this config format is shadcn's and may change.)

# Repo layout (github.com/DavidHDev/react-bits)

Vite + React docs site that also builds the component registry. Snapshot: commit `37f53df` (2026-11-24, "add neon components").

```
src/content/<Category>/<Name>/        JS + CSS variant (Name.jsx + Name.css)
src/tailwind/<Category>/<Name>/       JS + Tailwind variant
src/ts-default/<Category>/<Name>/     TS + CSS variant
src/ts-tailwind/<Category>/<Name>/    TS + Tailwind variant
src/constants/Information.js          componentMetadata: name, description, category, tags, added, updates, variants
src/constants/Categories.js           sidebar categories
src/demo/<Category>/                  demo pages shown on the docs site
src/tools/                            Background Studio, Texture Lab, Shape Magic, Center Stage, Sound Lab
public/r/<Name>-<LANG>-<STYLE>.json   built shadcn registry items (generated; 1287 files at snapshot)
public/llms.txt                       agent-oriented index (generated by scripts/generateLlmsText.js)
jsrepo.config.ts                      registry definition; builds the 4 variants per component
scripts/generateComponent.js          `npm run new:component` scaffold
```

Categories: `Animations`, `Backgrounds`, `Components`, `Micro`, `TextAnimations`.

## Run locally

```bash
git clone --depth 1 https://github.com/DavidHDev/react-bits.git
cd react-bits && npm install && npm run dev   # docs site + registry watcher
npm run registry:build                        # regenerate public/r
npm run check:prop-docs                       # verify defaults match across 4 variants + docs
```

## Contributing rules (CONTRIBUTING.md)

- Branch name `feat/<feature-name>`; PR to `main`.
- Every component change must be mirrored in all 4 variants, and user-visible changes need an `updates: [{date, note}]` entry in `src/constants/Information.js`.
- New community components are currently NOT accepted; only enhancements and bug fixes.
- Test on desktop and mobile, check the console, run `npm run check:prop-docs`.

## Manual copy fallback

If the CLI is unavailable: copy the whole component folder for your variant, install its dependencies (see catalog), and for CSS variants keep the `.css` file beside the component.
